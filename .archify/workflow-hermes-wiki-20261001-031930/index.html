아키텍처와 워크플로

자료를 읽는 경로, 에이전트가 답하는 경로, 원문을 모으고 지식을 게시하는 경로를 분리해 봅니다. 전체 기술문서를 여덟 개의 Archify 다이어그램과 근거 안내로 정리했습니다.

구현·운영 완료를 뜻하지 않습니다. BFF·화면·격리는 제안입니다. 기술문서의 관측 시점과 현재 상태를 혼합하지 않으며, 시각화가 실행·자료 전송·게시 권한을 부여하지 않습니다.

  1. 01전체 시스템 구조 architecture

    브라우저 → TLS → BFF. 모델 없는 읽기와 승인된 질의를 분기하고 수집·게시를 별도로 둡니다.

    JSON 원본문서 근거
  2. 02작업 경로와 접근 격리 architecture

    terminal.cwd, placeholder·fallback, 실제 도구 위치, 프로젝트 지침과 OS 권한의 차이.

    JSON 원본문서 근거
  3. 03모델 없는 탐색·읽기 workflow

    인증과 pageId 확인 → committed receipt·hash 검증 → 최소 DTO. 충돌을 완료본으로 캐시하지 않습니다.

    JSON 원본문서 근거
  4. 04질의·스트리밍·중지 workflow

    Runs 접수, 단일 upstream SSE, fan-out, 상태 재조회와 stop. 연결 취소는 실행 중지가 아닙니다.

    JSON 원본문서 근거
  5. 05HTML 우선 원문 수집 workflow

    승인 검색·한도·버전 확인. 공식 HTML 미제공일 때만 같은 버전의 PDF 원본을 보관합니다.

  6. 06컴파일·조건부 게시 workflow

    별도 승인 → 원문 읽기·검토 → 공유 lock·최종 hash·WAL → committed와 실물 확인.

  7. 07데이터·화면·상태 계약 architecture

    파일 원장 → 안전한 projection → 사용자 화면. 원문·컴파일·게시·검토·실행 상태를 분리합니다.

섞지 말아야 할 완료

  • HTML 미제공 ≠ 원문 미확보
  • API 접수 ≠ 실행 종료
  • API completed ≠ Wiki 게시
  • committed ≠ 인간 검토

사용 방법

제목을 누르면 독립 HTML 다이어그램이 열립니다. 브라우저 뒤로 가기로 목록에 돌아옵니다. 각 JSON은 수정 가능한 명세이고 근거 파일에는 원문 줄 범위가 있습니다.

내용은 모두 한국어입니다. 01–06의 Viewer 조작 UI는 영문, 07–08은 한국어입니다. 자동 브라우저 검사와 이미지 기반 시각 검토는 별도로 기록합니다.

도식은 데스크톱 열람을 권장합니다. 375px에서 일부 노드가 화면 밖에 있고 보조 글씨가 작습니다. 모바일 전체 가독성·접근성 PASS는 아닙니다.

원문의 과거 관측값에 관한 주의

README와 verification.json의 원문 보관·컴파일 숫자는 문서 작성 당시 snapshot입니다. 이후 실행 결과와 합쳐 현재 상태로 표시하지 않습니다. 이 패키지는 원문 문서와 기존 슬라이드를 보존하고 Gateway·모델·Cron·Wiki 지식 게시를 실행하지 않습니다.
