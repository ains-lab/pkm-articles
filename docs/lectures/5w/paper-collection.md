## 2. 자동으로 하는 일과 하지 않는 일

| 자동으로 하는 일 | 자동으로 하지 않는 일 |
| --- | --- |
| 정해 둔 주제의 논문 찾기 | 논문 요약·번역하기 |
| 이미 가진 논문인지 확인하기 | 그림·표를 따로 잘라 저장하기 |
| HTML을 우선 저장하고, 공식 미제공이면 같은 버전 PDF 원본 저장하기 | PDF를 읽어 글자를 뽑거나 다른 파일로 바꾸기 |
| 제목·버전·파일이 제대로 저장됐는지 확인하기 | 논문을 모델에 보내 미리 구조를 다시 만들기 |
| 저장 성공·미제공·실패를 구분해 기록하기 | 지식 페이지를 자동으로 만들기 |

**HTML을 먼저 확인하고, 공식 HTML 미제공이 확인된 경우에만 같은 버전의 공식 PDF 원본을 받습니다.** 접속 차단이나 일시 오류를 PDF 대체 사유로 삼지는 않습니다.

## 3. 매일 어떤 순서로 움직이나요?

1. **예약 알람이 울립니다.** 한국 시간으로 매일 밤 12시입니다.
2. **지난번 표시를 확인합니다.** 어디까지 찾았는지 적어 둔 책갈피 같은 기록을 읽습니다.
3. **주제에 맞는 논문을 찾습니다.** 현재 주제는 AI 에이전트의 보안·안전입니다. 정확한 검색 문구는 [설정 파일](../../../_meta/topics.json)에 있습니다.
4. **중복을 확인합니다.** 같은 논문의 같은 버전이 있으면 파일을 확인하고 다시 저장하지 않습니다.
5. **해당 버전의 HTML 원본을 우선 받습니다.** 공식 HTML 미제공이 확인된 때만 동일 버전 PDF 원본을 받습니다. 논문 내용이나 링크는 바꾸지 않습니다.
6. **파일을 확인하고 목록을 갱신합니다.** 제대로 받은 파일만 정식 원본 폴더에 넣습니다. 못 받은 이유도 남깁니다.

처음 시작할 때는 최근 24시간을 찾습니다. 그다음부터는 마지막으로 확인한 지점을 기준으로 앞쪽 48시간을 겹쳐 확인합니다. 놓친 갱신을 찾기 위한 장치입니다. 다만 처음 정한 검색 시작점보다 더 오래된 자료로 범위를 넓히지는 않습니다.

이번 정책 변경에서는 기존에 승인됐지만 전문을 확보하지 못한 `2609.30614v1`, `2609.30824v1`의 PDF 수집 대기만 검색 시작점 예외로 허용합니다. 다른 과거 논문을 새로 찾으라는 허가는 아닙니다. 정책 변경 작업 자체에서는 다운로드하지 않습니다.

하루에는 **최대 5개의 서로 다른 논문 버전을 처리 시도**합니다. 못 받았거나 HTML이 없는 논문도 이 한도에 포함됩니다. 같은 ID의 HTML 확인과 PDF 대체 수집은 합쳐 한 번이며, 대기 목록 등록만으로 시도를 세지는 않습니다. 매일 반드시 5편을 저장한다는 뜻은 아닙니다.

## 4. 파일은 어디에 있나요?

저장소 위치는 `/home/ainsdev/wiki/pkm-articles`입니다.

실제로 저장된 논문 하나를 예로 들면 다음과 같습니다.

```text
raw/articles/4cff5b4f10ec/
├── index.md                        # 이 주제의 논문 목록
└── arxiv-2609.30217v1/
    ├── source.html                 # 논문 HTML 원본
    └── source.json                 # 제목·주소·버전·파일 확인 정보
```

- `4cff5b4f10ec`는 이 수집 알람의 고유 이름표입니다. 주제별 보관함을 나누는 데도 사용합니다.
- `2609.30217v1`은 논문 번호와 버전입니다. `v1`은 첫 번째 버전을 뜻합니다.
- `source.html`은 arXiv가 보내준 논문 파일 그대로입니다.
- `source.json`은 파일 옆에 붙인 메모지입니다. 제목·저자·원래 주소·저장 시각 등을 적습니다. 논문을 다시 쓴 요약본이나 파싱 결과가 아닙니다.

HTML 미제공으로 PDF를 저장할 때는 `source.html` 대신 `source.pdf`와 `source.json`만 둡니다. **한 버전 폴더에는 원본 한 파일과 관리 JSON 한 파일**을 보관합니다. 기존 HTML의 `arxiv-html-source/v1` 계약은 그대로 두고, PDF에는 `arxiv-pdf-source/v1`과 `pdf_file`·`pdf_bytes`·`pdf_sha256`을 사용합니다.

별도 데이터베이스는 없습니다. 원본과 작은 관리 파일로 보관합니다.

## 5. 같은 논문을 또 만나면요?

책 제목만 비교하지 않습니다. **논문 번호와 버전**을 함께 확인합니다.

- 같은 번호·같은 버전이면: HTML이든 PDF든 기존 파일을 확인하고 재사용합니다. PDF를 이미 저장했다면 HTML을 자동 재확인하거나 형식을 바꾸지 않습니다.
- 같은 번호의 새 버전이면: 새 폴더에 따로 저장합니다.
- 같은 버전·같은 형식인데 받은 내용이 달라졌으면: 기존 파일을 덮어쓰지 않고 확인이 필요한 문제로 기록합니다. HTML과 PDF의 해시를 서로 비교해 충돌로 보지는 않습니다.
- 다른 주제에서도 같은 논문이 필요하면: 원본을 또 복제하기보다 기존 원본 위치를 연결합니다.

파일 확인에는 **SHA-256 해시**, 즉 파일 내용이 같은지 비교하는 표식을 사용합니다. 이 표식이 맞는다고 논문의 주장까지 참으로 검증된 것은 아닙니다.

## 6. HTML이 없거나 받다가 실패하면요?

| 상황 | 처리 |

| PDF 원본 저장·검증 성공 | 원문 확보로 셉니다. HTML 미제공 근거는 유지하며 HTML을 자동 재확인하지 않습니다. |
| HTML과 PDF가 모두 공식 미제공 | 전문 미확보로 남기고 7일 후 재확인 대기로 기록합니다. |

| 다른 수집 작업이 이미 진행 중 | 동시에 파일을 쓰지 않고 이번 실행을 건너뜁니다. |
| 검색·다운로드·파일 확인의 핵심 실패가 3회 연속 발생 | 안전 표시를 켜고 후속 처리를 막습니다. 별도 점검이 필요합니다. |

논문 소개 페이지나 PDF 변환본을 HTML 전문처럼 저장하지 않습니다. HTML 재확인 예정일은 PDF 수집 대기를 막지 않으며 PDF 재시도는 별도의 대기 시각과 서버의 `Retry-After`를 따릅니다. 위의 안전 표시는 **수집 내부의 중단 조건**이며, Cron 예약 자체의 일시정지와는 다릅니다.

예약 시간을 놓쳤다면 다음 실제 실행에서 마지막 검색 기록을 이어갑니다. 놓친 날짜 수만큼 작업을 한꺼번에 반복하지 않습니다.

## 7. “확인”과 “전처리”는 무엇이 다른가요?

**확인은 책이 제대로 도착했는지 보는 일입니다. 전처리는 책의 내용을 잘라 새 모양으로 만드는 일입니다.**

지금 남아 있는 확인은 다음과 같습니다.

- 요청한 논문과 버전이 맞는가?
- 오류 안내가 아니라 요청한 형식의 원본을 받았는가?
- 응답 전송이 정상 종료됐고 길이·형식 표식이 맞는가?
- 저장한 뒤에도 크기와 해시가 일치하는가?

PDF는 HTTP 200·`application/pdf`·공식 동일 버전 최종 URL·`%PDF-` 시작·끝부분 `%%EOF`·전송 길이·해시만 확인합니다. 이것이 PDF 내부 내용의 완전성이나 페이지 수까지 검사했다는 뜻은 아닙니다. 제목·저자 등은 동일 버전의 실제 서지 기록으로 확인합니다.

반대로 본문 뽑기, 그림·표 분리, 이미지 만들기, OCR(그림 속 글자를 읽어 글자로 바꾸기), Markdown 변환, 모델을 통한 사전 구조화는 하지 않습니다. 전처리 전용 환경과 프롬프트도 제거했으며 PDF 원본 보관을 위해 복원하지 않습니다.

Hermes 자체는 여전히 모델을 이용해 검색 도구와 파일 작업을 조정합니다. **없앤 것은 논문을 따로 보내 처리하던 전처리 모델 호출**이지 Hermes 에이전트 자체가 아닙니다.

## 8. 논문을 Wiki로 정리하고 싶으면요?

다음처럼 따로 요청하면 됩니다.

> “저장된 2609.30217v1 원본 HTML을 직접 읽고, 핵심 방법과 한계를 한국어 논문 페이지로 정리해 주세요.”

그러면 `llm-wiki`가 원본 HTML을 직접 읽습니다. 미리 파싱한 중간 파일을 만들 필요는 없습니다. 읽은 내용을 논문 노트, 개념 노트, 비교표, 질문과 답변으로 정리하고 원문 위치를 연결합니다. PDF만 보관된 논문은 별도 요청에서 읽기 방식과 범위를 확인해야 하며, PDF 저장 성공이 읽기·파싱·컴파일 승인은 아닙니다.

이때에도 “저자가 한 주장”과 “우리가 해석한 내용”을 구분합니다. 안 읽은 부분과 안 본 그림은 미확인이라고 적습니다. 구체적인 기준은 [직접 컴파일 전략](../../../_meta/COMPILATION.md)에 있습니다.

## 9. HTML 원본 보관과 외부 자산의 한계

웹페이지는 그림이나 글꼴을 다른 주소에서 불러오기도 합니다. 지금은 그런 파일을 따로 모으지 않습니다. 따라서 로컬 HTML을 열었을 때 그림이나 모양이 일부 빠질 수 있습니다.

그렇다고 원문에 그림이 없다고 판단하면 안 됩니다. `source.json`에 적힌 같은 버전의 arXiv 주소를 기준으로 확인해야 합니다. 모든 그림까지 인터넷 없이 볼 수 있도록 묶어 둔 저장 방식은 아닙니다.

또한 논문 속 코드나 지시는 **읽을 자료**입니다. 자동으로 실행하라는 허가가 아닙니다.

| 항목 | 관측한 상태 |

| 실제 PDF 원본 저장 | 0편 |

| 마지막 실제 수집 | 기존 HTML 전용 정책으로 정상 검색, 신규 후보 0편 |
| 재활성화 후 다음 예정 | UTC `2026-09-29T15:00:00+00:00` = KST 2026-09-30 00:00; 실제 실행 완료가 아님 |

HTML 미제공 논문은 `2609.30614v1`, `2609.30824v1`입니다. 사용자 승인에 따른 과거 PDF·전처리 산출물 영구 삭제 이력은 유지합니다. 새 정책은 삭제한 파일이나 백업의 복원이 아니라, 이 두 편을 동일 버전 공식 PDF 수집 대기로 등록하는 것입니다. 실제 PDF 저장 전에는 전문 미확보이며, 이 정책 변경에서는 다운로드하지 않습니다. 대기 등록·현재 상태는 [state](../../../_meta/state/4cff5b4f10ec.json), 변경 근거는 [정책 전환 폴더](../../../_meta/migrations/20260929T034401Z-pdf-fallback-policy/)에서 확인합니다.
