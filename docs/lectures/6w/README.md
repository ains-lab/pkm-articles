# 6주차 — Hermes × Agent Reach SNS Second Brain

> 문서 작성·설계 범위: X·Reddit·YouTube의 공개 자료를 **수집 → 불변 `raw/` 보관 → 승인된 Wiki 컴파일 → 질의·검토**로 관리합니다. Discord용 요약문 생성·전송·Webhook은 제외합니다. Wiki 내부의 요약·분석은 컴파일에 포함합니다.
>
> **중요한 확인 한계:** 2026-10-01 현재 `default` 프로필에서 요청한 Cron `0d0ad6c887e3`을 찾지 못했습니다. 이 문서는 그 잡의 설정을 복원한 문서가 아닙니다. 확인된 Hermes 기능·Agent Reach 명령·저장소 계약을 기반으로 작성한 **적용 전 설계**이며, 원래 잡의 일정·검색식·모델 등은 미확정입니다.

## 학습 목표

1. Cron은 예약·실행 조정, Agent Reach는 접근 수단 안내, `llm-wiki`는 지식 컴파일이라는 역할을 구분합니다.
2. 검색 결과·댓글 일부·자막을 플랫폼 전체 원본으로 오인하지 않고 읽은 범위와 한계를 기록합니다.
3. 원천 ID·캡처 해시·인용 위치로 지식의 근거를 추적합니다.
4. 수집 성공, 컴파일 성공, 로컬 게시, 인간 검토를 서로 다른 상태로 관리합니다.
5. 단순 뉴스 누적을 넘어서 개념·비교·질의·개인 연구 피드백을 연결합니다.

## 한눈에 보는 구조

```text
사용자 승인: 주제·공개 범위·계정·댓글·언어·보관·모델 전송·게시
                              │
                     [수집 전용 Cron A]
                              │ agent-reach 스킬로 경로 선택
              ┌───────────────┼────────────────┐
       X: twitter-cli   Reddit: rdt-cli   YouTube: yt-dlp
        보호된 인증      보호된 인증       메타데이터·자막
              └───────────────┼────────────────┘
                       임시 출력 /tmp
                              │ 식별자·범위·오류·민감정보 검사
                    [Wiki 원천 보관 경계]
                              │ 불변 파일·해시·source.json
                  raw/social/<platform>/...
                              │ committed 캡처 manifest만
                     [별도 컴파일 B]
                    승인된 llm-wiki 실행
                              │ 생성 → 근거 검토 → 조건부 게시
         entities/ ↔ concepts/ ↔ comparisons/ ↔ queries/
                              │
                    index.md / append-only log.md
                              │
                     사용자 질의·검토·피드백
```

화살표는 제안한 데이터 흐름이지 구현·실행 증거가 아닙니다. 새로운 DB, 임베딩 서비스, 커스텀 수집기·파서 프로그램은 만들지 않습니다. 표준 도구의 출력과 파일 기반 Wiki를 활용합니다.

## 가장 작은 적용 순서

1. 대상 Cron의 비밀값을 제거한 원설정 또는 실제 소속 프로필을 확인합니다.
2. [현재 SCHEMA](../../../SCHEMA.md)와 [AGENTS](../../../AGENTS.md)에 SNS 원천·모델 입력 범위를 추가하는 승인을 받습니다. 문서 작성은 정책 변경 승인이 아닙니다.
3. 공개 항목을 채널당 하나씩 승인하여 수집·보존만 시험합니다.
4. 저장된 정확한 캡처를 별도로 승인하여 신규 draft 노트만 컴파일합니다.
5. 중복·부분 실패·동시 편집·중단 복구를 확인한 뒤, 필요 시 전용 잡을 paused로 등록합니다.
6. 원래 잡과의 중복을 정리하고 별도 활성화 승인을 받습니다.

현재 논문용 Cron `4cff5b4f10ec`와 paused 컴파일 잡 `4839be6a1db1`에 SNS를 넣지 않습니다. SNS는 논문과 다른 원천 계약을 필요로 합니다.
